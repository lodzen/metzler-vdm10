ISAPI endpoints registered by hicore (VDM10 indoor, fw 2.0.24)

Complete catalog of the HTTP-XML (ISAPI) routes compiled into this unit’s hicore binary — recovered by walking the URI routing table in .data (the hicore ELF from the unpacked rootfs — re-derivable from the .dav, see ANALYSIS.md), not from generic Hikvision documentation. Reproduce with tools/dump_isapi_table.py.

Table format (verified): each route is a 0x68-byte record {name* @+0, handler* @+4, unused @+8, childTbl* @+0xc, one @+0x10, methodFlags @+0x14, …zero pad}; rows of a table are contiguous and a /<parent>-named row terminates it. childTbl points at a nested table; index-named rows are /<id> parameterized-segment placeholders — all inert in this build (handler 0, no children): parent dispatchers parse numeric ids out of the path themselves.

methodFlags @+0x14 (inferred): bit0 = GET, bit2 = PUT, bit4 = row has a parameterized child table; bit1 = a second write verb († POST or DELETE — dispatchers compare the method id in param_2[2], where 1=GET and 4=PUT are confirmed). ⁺ = has /index child. Nonzero flags on handler-less dir rows likely still describe the subtree’s verbs.

Handler column = registered dispatcher vaddr. Names resolve via vdm10_1.0/names/isapi.tsv + vdm10_1.0/isapi/*.c provenance (/* 0x<addr>); most handlers are 4-8-byte entry stubs (cmp r1,#0; movne r0,#0; push) that fall through to the named body. Empty name = no recovered symbol nearby.

11 groups, 189 rows, 146 dispatcher endpoints: System, VideoIntercom, Event, Security, Image, AccessControl, Streaming, SecurityCP, ContentMgmt, SmartLock, SingleSmartLock

Caveats / unknowns

  • Method semantics live inside each dispatcher (param_2[2]: 1=GET, 4=PUT confirmed); the † bit1 verb (POST or DELETE) isn’t rewritten yet — the flag word is the authoritative allowed-method hint per route.

  • ▸ = directory nodes; index = /<id> wildcards, all with handler 0 in this build — ids resolve through the parent dispatcher.

  • /ISAPI/ContentMgmt/logSearch registers a 2-instruction stub (mov r0,#0xd; bx lr) — route exists, functionally disabled.

  • /ISAPI/Image/channels self-nests (…/channels/channels) — genuine table self-reference; image endpoints are empty on this headless unit.

  • SmartLock/SingleSmartLock: mostly directory+capabilities stubs — wireless-lock actions largely absent in this build.

  • Two capabilities rows sit in the SystemSwitchCfg child block — the table literally contains both (first match wins at dispatch).

  • The flag bit on handler-less dir rows (Linkage, Streaming/index, BasicParam… all GET+PUT/GET) describes subtree verbs, not a callable handler.
