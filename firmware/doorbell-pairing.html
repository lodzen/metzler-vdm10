Doorbell pairing & door↔indoor signaling — firmware internals

How hicore (Metzler VTH 2.0.24, rebranded Hikvision indoor station) pairs with an outdoor door station: who registers where, the “Pre-Regist” number-assignment exchange, unlock credentials, keepalives, and the visNet TCP :8102 channel. Extension-facing registrar details: intercom-registration.md; wire dialect: ../protocol.md. Sources: vdm10_1.0/sip/{client/ registration.c,xml_proc.c}, vdm10_1.0/misc/net_sipClient_{sip_client, visNetServer}.c.c, vdm10_1.0/visnet/visnet_server.c, vdm10_1.0/misc/dataManagement_database_db_api.c.c, vdm10_1.0/isapi/videointercom{,_do}.c.

1. Pairing model — who registers with whom

The system is a tree; every “inner device” has one configured parent whose IP lives at cfg+0x5fe8 (the “regist ip” block):

Every station runs the same code (task_sipServer :5065, eXosip UAS :5060, visNet server :8102); roles come from cfg flags (srv_isIndoor_w, netAltRoute, netDualNic, cfgFlagC/F/H/J). Two link mechanisms coexist:

  • Config-time pairing — ISAPI/iVMS writes the topology into cfg (§2); a statically numbered device then only does plain REGISTER (ANALYSIS.md §4: pre-registration “only needed if the door station requires it”).

  • Runtime pre-registration — a device whose own devLongNum (cfg+0x2d354) is empty sends a Pre-Regist SIP MESSAGE to the parent and receives its number in the reply (§3).

2. Config-time pairing (iVMS / ISAPI)

PUT RelatedDeviceAddress (isapiIntercomRelatedDeviceAddrBasic @0x001ce5c8 → isapiApplyVisRelatedDevice @0x001d6fc8, isapi/videointercom{,_do}.c) carries the topology: <MainRoomAddress> · <MainOutdoorAddress> (the door) · <ManageAddress> · <SIPServerAddress> · <CenterAddress> · <AgainAddress> (secondary door) · <MainOutdoorType> (mainOutdoor→1 / mainVilla→2 → cfg+0x6018) · doorRoomNetBuildMode · centerPort. sdkSaveVideoIntercomRelateDevCfg applies it → sess_cfg_notify() posts registration-change msgs to task_sipClient_RegistCtrl, which drops the eXosip rids and — when cfgFlagF()!=0 and the old devLongNum is 11 digits — parks it at cfg+0x2d364 (param_commit_lock()) and clears cfg+0x2d354, priming the next Pre-Regist to delete the stale binding. Factory door-block defaults (util_common_visUtil.c.c ~0xf93e8): cfg+0x350ce=60 (expire min), cfg+0x35040=0x13c4 (5060), cfg+0x5fe8=192.0.0.65 only when cfgFlagF()!=0.

3. Runtime pre-registration — “Pre-Regist”

3.1 Trigger (client side — task_sipClient_RegistCtrl 0xe0dc4, sipcli_voip_reg_task 0xe1a04)

  • reg_guard_check() @0x000db610: netAltRoute()!=0 and cfg+0x5fe8 set and FUN_000f7ef8(cfg+0x2d330)==1 (dev num resolvable); on non-type-2 systems also u16@cfg+0x2d336 < 1000.

  • own devLongNum slot empty (guard fields DAT_000e19d4/0xe230c, inferred cfg+0x2d354 — reply store and failure memset(cfg+0x2d354) both target it) → sipcli_send_msg(&blk,"Pre-Regist",flag): flag=1 in voip_reg_task (adds <sipNum>), −1 in RegistCtrl. Failure → "Inner device pre-register to door failed!" → retried.

3.2 The MESSAGE on the wire

sipcli_send_msg (@0x000dc9b0) builds MESSAGE sip:Pre-Regist@<parent-ip>:5060 (method 3 → 0x13c4, the UAS — not the registrar), From: sip:%05d@<localip> (%05d room number), Content-Type: text/xml, body from _sip_xml_get_sip_info_xml (@0x000ea910):

<from><deviceSN>…</deviceSN><ipAddr>10.0.0.x</ipAddr></from>
<to><ipAddr><parent-ip></ipAddr></to></header>
<body><roomNum>00101</roomNum><delFlag>1</delFlag>
<delLongNum>10010100000</delLongNum><floorNum>3</floorNum>

3.3 Parent side — assign & reply (sipcli_on_msg @0x000ddbc8, m3 a1)

  1. Gates cfgFlagC()==0 && cfgFlagJ()==0 and cfgFlagH()==0 (cfg meanings unresolved); own devLongNum must be 11 chars else 0x191.

  2. Assigned call_num = own type-digit + own floor + own unit + roomNum (T FFF UU + string) — the parent prefixes the child’s number.

  3. dpi_pre_register_dev_reg_info (@0x000fc24c): where call_num='<assigned>' absent → delete where call_num='<delLongNum>' (when delFlag), insert 0xb0 dev_reg row {call_num=assigned, dev_ip=requester, reg_time=now, dev_type=3} into vis.bin table 10. Present (ret 4) → serial == requester deviceSN → 200 (idempotent re-pair); different device → 0x192; other errors → 400.

  4. Reply = a separate MESSAGE (not a 200 body), method 5 action 2, from/to swapped + parent’s deviceSN, to the requester address taken from the request event, port 5060: <body><responseStatus>200|400|401|402 </responseStatus><roomNum><assigned devLongNum></roomNum></body> — skipped when srv_isIndoor_w()==1 (indoors don’t serve Pre-Regist).

3.4 Child side — reply handling (same function, m5 a2)

responseStatus==200 → clear cfg+0x2d364/cfg+0x2d354, copy reply roomNum into cfg+0x2d354 (now own devLongNum), writeDevParam() persists, flags *DAT_000de554=0/*DAT_000de558=1, mq post. 0x191 → registered flag cleared; 0x192 → “number in use” (=1, &0xfffe).

7. Main vs extension

  • reg_guard_check requires netAltRoute()!=0 (the “isRoomMain”-style flag) → Pre-Regist is a main-device path in this binary; extension indoors only kind-1/kind-8 REGISTER to the main indoor.

  • Only the main indoor pushes unlock/hijack passwords (§5) and pulls the sub-door list (§9).

  • The main indoor also plays parent for extensions: same sipcli_on_msg m3 handler + :5065 registrar + :8102 visNet server (0x2018 ext-record ingest, 0x2033 reg-table push after each extension REGISTER — intercom-registration.md §8). Its cfgTalkbackFlag loop variant (sipcli_voip_reg_task) sends Pre-Regist with flag=1 (+<sipNum>).

8. visNet channel — TCP :8102

Optional proprietary channel, separate from SIP (vdm10_1.0/visnet/visnet_server.c). Direction: whichever side needs something connects to the peer’s :8102 — indoor→door for unlock/subdoor/passwd, door/main→extension for table push/relay. Server taskVisNetServ @0x000f4d80 → per-conn taskVisClientReq @0x000f2a28.

Auth (verified): on accept the server sends fixed 200-byte serverInfo (+0x08 = nonce[0x40] = hex-MD5 of "Vis:Hikvision:<asctime>"). Every cmd = 0xac header + payload: +0x00 u32be len · +0x08 u32be netCmd · +0x0c keySeed · +0x14 clientNum[0x10] (own devLongNum) · +0x24 longNum[6] · +0x2c nonce echo · +0x6c signature[0x40] · +0xac payload. visNetServerDeserializeCmd @0x000f1b08 rejects nonce/signature mismatch (“Illegal nonce package” / “Illegal signature package”); the signature is hex-MD5 over the frame with sig field zeroed (integrity, not a keyed MAC); payload XOR’d with 0x5577aabb ^ fold(nonce). Replies {u32be len, u32be code,…}; 1 = ok.

9. Sub-door support

“Sub-doors” = secondary outdoor units under the main door, enumerated without SIP: vns_subdoorReq(0) → cmd 0x2004 to cfg+0x5fe8:8102 (main door), vns_subdoorReq(1) → cfg+0x601c (again door); the 0x224 reply {num, 0x40-records {devLongNum, subDoorIp}} → sess_door_tbl_fill/ sess_again_tbl_fill (“room get subdoor info from maindoor.”). Server side visNetServSubdoor builds the list via sipcli_dev_search. On failure (non-indoor) → "set ezviz maindoor zero" + local fallback sipcli_door_reg (@0x000e2d1c) fabricating rows "main:%d-%d-%d"/"sub:%d-%d-%d-%d" with ip=cfg+0x5fe8, port 0x22a (554 — door RTSP), user admin — the table driving door-camera pulls and unlock targets. The SIP-side mirror is videoIntercomMsg method 5 action 7: <subDoorInfo> × ≤8 of <devLongNum> +<subDoorIp> (inferred door→indoor subdoor-list response — no sender site in this binary). Dual-NIC mode uses vns_doorReq against cfg+0x6034 (visNetClientdoor, g_mainDoor @0x00778660).

Gaps / unverified

  • DAT_000e19d4/0xe230c assumed cfg+0x2d354 (devLongNum); roomNum / floorNum / interval cfg fields (DAT_000e19e4, DAT_000e2340, DAT_000e2338) likewise inferred from usage.

  • Senders of method-2 / method-3a3 / method-5a1/a4/a7 (password & subdoor payloads): vocabulary verified, sender sites live in door-side code not in this indoor binary (directions marked inferred).

  • Exact cfgFlagC/F/H/J semantics; visNetServSubdoor reply magic (0x1000000/0x2000000) meaning; whether 0x2033 reg-table pushes reach indoors (push is 1000000000-filtered → extension-style numbers).
