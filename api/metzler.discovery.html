metzler.discovery module

LAN discovery for VDM10 devices (stdlib only, no dependencies).

Two mechanisms, both verified against live firmware V2.0.24:

  1. SADP inquiry (Hikvision Secure Active Discovery Protocol): an XML <Probe> to the multicast group 239.255.255.250:37020 (plus optional unicast sweep - multicast may be filtered). Outdoor stations answer with a <ProbeMatch> XML (DeviceType/DeviceDescription/DeviceSN/MAC/IPv4). The indoor units run the SADP client side (sadpc_*, confrelatedev_check_doorDev) to find doors but do not answer inquiries.

  2. Registrar fingerprint: a kind-1 indoor REGISTER to host:5065. The main indoor’s registrar replies to source-ip:5060 - htons(5060) is hard-coded in send_reply (vdm10_1.0/sip/server/registrar.c), NOT the Via port - so the probing socket must bind :5060. Any SIP reply means a registrar is present (main indoor); extension indoors have no registrar and stay silent. Status codes map extension-slot state: 410 Sip Gone = number taken by another device, 200 OK = slot free - but a 200 inserts a dev_reg row, so every probe is followed by an Expires: 0 unregister to clean up (verified: 200 OK).

metzler.discovery.discover(timeout=3.0, subnet=None, local_ip=None)[source]

full LAN sweep -> {“doors”: […], “registrars”: […], “candidates”: […]}

  • doors: SADP ProbeMatch dicts of outdoor stations (DeviceType 57619 or VDM10 OUI)

  • registrars: hosts that answered the :5065 REGISTER fingerprint - i.e. the main indoor (extension indoors stay silent)

  • candidates: hosts with the Hikvision TCP signature that were neither SADP responders nor registrars - shown as “possible indoor” fallback

metzler.discovery.provider_status(host: str, port: int, user: str, password: str, domain: str, local_ip: str, timeout: float = 6.0) → int | None[source]

REGISTER user at a standard SIP server; returns the reply code.

For the config flow’s provider/trunk check: REGISTER -> one digest retry on 401/407 -> status. A 2xx is followed by Expires: 0 cleanup. None = unreachable/timeout. Unlike the intercom registrar, providers answer on the Via’s source port — an ephemeral bind suffices.

metzler.discovery.register_status(registrar: str, sipnum: str, serial: str, local_ip: str, port: int = 5065, wait: float = 0.8) → int | None[source]

Probe-REGISTER sipnum on registrar and return the reply code.

For the config flow’s registration check: 200 = the extension can be claimed (the probe row is removed again via Expires: 0 inside _slot_status), 410 = held by a different device, 401/403 = the registrar challenged auth, None = unreachable or :5060 busy. serial should be the entry’s own so the dedup verdict matches what the real registration will see.

metzler.discovery.registrar_probe(host, ext=None, timeout=3.0, listen_port=5060, reg_port=5065, serial='Q12345678', mac='02:00:11:22:33:44', floor=3, local_ip=None)[source]

REGISTER fingerprint -> SIP status int, or None when the host is silent.

The probe binds listen_port because the VDM10 registrar replies to source-ip:5060 unconditionally (send_reply hard-codes the port). On a 2xx answer the probe registered an extension, so an Expires: 0 unregister is sent immediately to remove the dev_reg row again.

metzler.discovery.scan_extension_slots(host, slots=range(0, 6), **kw)[source]

probe {base}{slot} for each slot -> {ext_number: status|None}.

Live semantics: 410 = slot taken by a device, 200 = free (slot row is removed again by the probe’s unregister follow-up), None = no registrar.
