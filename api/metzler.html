metzler package

Metzler/Hikvision indoor-station simulator and SIP bridge.

Simulates a VTH extension on the private intercom registrar, accepts intercom/door calls in the firmware’s SIP dialect and bridges them to a standard SIP provider/PBX or the local headset. See docs/architecture.md and docs/protocol.md; wire details in ANALYSIS.md.

uv run indoor-station # or: python -m metzler / __main__.py

–server 10.0.0.38 # registrar (main indoor :5065) –username 10000000003 # extension number (SIP user) –password secret # extension password (iVMS/SIP config) –local-ip 10.0.0.96 # this host –sip-host sip.linphone.org # SIP provider proxy/registrar –sip-user alice –sip-pass secret –sip-target sip:alice@sip.linphone.org

Asterisk / PBX trunk (no provider REGISTER when –sip-user/–sip-pass are empty; a bare extension is expanded to sip:<ext>@<sip-host>):

–sip-host 192.168.0.20 –sip-target 6000 [–no-sip-srtp]

Stdlib only at module level. SRTP (default on for the provider leg) lazily uses the optional cryptography package; a peer that refuses the SRTP offer with 488 is re-offered plain RTP.

stream(conn, wlock, playing, chmap, ssrcs)[source]

send the stream exactly like a real indoor unit serves it: the SDP advertises video+audio (their client requires the video track), but on the wire the unit emits ONLY PCMU audio - 320B payloads, 40 ms, ts += 320 @8kHz - never a single video RTP packet (verified from a live pull of the main indoor’s :554 during an extension call: 1.5 MB, all ch2 PT0 320B, zero ch0). The RTP ssrc must equal the one we declared in the SETUP reply or their player drops the packets.

provider-mode media for intercom calls (header-only SDP): pulls the caller’s rtsp://<caller>:554 PCMU and forwards it as RTP (PT0) to the SIP peer; incoming SIP peer RTP feeds RtspServer.mic so the caller’s pull hears the peer. called by RtspServer.stream - one 160B/20ms ulaw frame of PEER audio. Shed to ~8 frames (160ms) first: the queue fills while early media arrives before the caller’s pull runs, and serving oldest-first would lock that backlog in as a constant delay for the whole call (the fill and drain rates match once the call is up).

class metzler.SipProvider(st, o)[source]

Bases: object

Standard-SIP trunk to a hosted provider (e.g. sip.linphone.org).

Everything the public-SIP side needs lives here so the station only ever delegates: REGISTER (digest auth, NAT learn via the echoed Via), one outbound INVITE leg per bridged Call, and ACK/CANCEL/BYE for that leg.

Packet flow:
station listener -> is_reg_response() -> reg_queue (REGISTER replies)

-> calls[Call-ID] -> handle_response() (INVITE replies)

on_invite bridge -> invite(call) (offer built by offer_sdp()) provider 200 OK -> station.provider_answered() -> ack() teardown -> cancel() / bye()

The provider object sends on the station’s UDP socket (shared source port) via the st back-reference; it owns no sockets of its own.

class metzler.Srtp(master_key, master_salt)[source]

Bases: object

One direction of an RFC 3711 SRTP stream, suite AES_CM_128_HMAC_SHA1_80 (the SDES default Linphone accepts). Key-derivation rate 0, no MKI. protect(): RTP -> SRTP for sending; unprotect(): SRTP -> RTP or None if the auth tag fails. RTCP is not protected (the bridge sends none).

metzler.sdp_answer_talkback(serial, ip, audio_port=None, video_port=None, opts=None)[source]

the real 200 OK SDP a hicore station emits when answering an EXTENSION call (sess+0x7c == 3 -> FUN_000dd18c header-only path, sip_client.c ~5968/6160). Header-only SDP + the same private session attrs as the offer:

doorFloor:0 responseType:<wait outcome> doorType:0 isSpecialType:<2|0> isConfirm:0

responseType = FUN_000dc2dc wait outcome: 0 = answered (200); the caller copies attr#1 -> sess+0x78 and attr#3 -> sess+0xcc and posts {+0x78,+0x7c,+0xcc} to the GUI (msg 0x80f; byte0==4 routes to the videocall window, else the initiate window).

isSpecialType — VERIFIED ON THE WIRE (real indoor 10000000001 @ .47, both its offer and its 200 OK send 2): 2 = “no remote video exists” -> the caller’s videocallProc skips the remote-video rect -> audio-call UI. 0 -> video rect drawn -> “video session” UI. Real indoor stations claim the special-model flag (isSpecialModel -> product-code band, FUN_00064da8). Default 2 to match; INDOOR_SPECIAL_TYPE overrides for A/B tests.
