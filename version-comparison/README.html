Firmware version comparison — V2.0.24 vs V2.2.100

Systematic side-by-side comparison of the two hicore indoor-station firmware builds analyzed in this repo. Read this first: registration.md — the registrar was rewritten and registration is where a SIP-1.0-era client (the simulator) actually breaks.

Caveats — read before trusting any line

  • Static analysis only. No V2.2.100 firmware was executed and no packet was captured from it. Wire behavior on error paths is predicted, not observed (the registration analysis explicitly refuses to predict a SIP status code for early exits — see VDM10_2.0/analysis/registration.md).

  • Trees: old-side citations use the vdm10_1.0/ rewritten pseudocode tree (and docs/firmware/*.md, ANALYSIS.md); new-side citations use VDM10_2.0/human_readable/ plus VDM10_2.0/decompiled/ raw exports and VDM10_2.0/analysis/. docs/firmware-v2/ may appear later and is not an input to this comparison.

  • Addresses are from the respective decompiles — V1 addresses are the old Ghidra project (ghidra_proj/hicore_proj), V2 addresses are the new project (ghidra_proj_v2/hicore_v2). They are not comparable across builds.

  • Names are an analyst overlay. On both sides the binaries are stripped; logical names come from self-identifying diagnostic strings and reviewed dataflow (_q suffix = uncertain). Old FUN_*/new FUN_* addresses are the reliable join key. New-side “reviewed behavior name” vs “diagnostic- recovered” vs “inferred” status is preserved where it matters.

  • Verified vs inferred is marked per claim: (verified) = read in decompiled code or recovered literals; (live-verified) = also seen on the wire (V1 only, ANALYSIS.md); (inferred) = interpretation the static evidence supports but does not prove; (extraction) = filesystem/package facts from the (now removed) fw_extracted//fw2_extracted/ trees, hashes preserved in VDM10_2.0/analysis/extracted-file-comparison.json.
