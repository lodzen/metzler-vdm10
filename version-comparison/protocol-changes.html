Protocol / message-format deltas — V2.0.24 vs V2.2.100

Wire-visible changes between the builds. V1 facts from docs/protocol.md, docs/firmware/intercom-registration.md, ANALYSIS.md (live-verified); V2 facts from VDM10_2.0/human_readable/ + VDM10_2.0/analysis/resolved-function-literals.json (static).

1. SIP method set — unchanged

Both stacks handle REGISTER, INVITE, ACK, BYE, CANCEL, MESSAGE, INFO, OPTIONS on the client leg (V2 cli_ua_task @0x00143340 diagnostics enumerate the same set: “receive MESSAGE new” / <locknumXML> / INFO / Signal= / OPTIONS / invite / ack / cancel / bye). Registrar still REGISTER + forwarding (sip_server_dispatch_method @0x00228d68, sip_server_route_invite @0x0022b780, sip_server_route_message @0x0022dc6c, sip_server_route_bye_or_cancel @0x0022f20c, VDM10_2.0/human_readable/sip/server/{dispatch,proxy}.c).

4. XML vocabulary

Unchanged roots/fields: regXML, regDevSerial, regDevMacAddr, regDevName, floorNum, sipNum, locknumXML/lockNum, ringXML/ noRingBack, videoIntercomMsg header/method/action/num, responseStatus, unlockPwd/unlockPasswd/hijackPasswd, delFlag, deviceSN, ipAddr, devLongNum, roomNum, floor, zone*, alarmTime, subDoorInfo, againdevice, ManageCenter, sipCmd.

New in V2 (verified literals, owners in parentheses):

  • Registration: <version>V2.0.0</version> in the request regXML (sip_xml_build_registration_identity @0x001216ac); <version>, <random>, <isSummerTime> in the response (sip_server_register_device @0x002291b8; parsed by client cli_reg_resp_proc @0x001318cc); regPassword fields (xml_parse_result_v2 @0x001237d8, isapi_set_iot_param @0x00315ecc, isapi_set_device_communication_to_json @0x0031fcb8); commPassword, commPasswordWithDoor, commPasswordWithConfirm (0x001237d8).

  • SIP2.0 message envelope (xml_getSipInfoXml_v2 @0x00120138, xml_parse_head_v2 @0x00124a08, sip/xml_proc.c): <version>, msgId, uri (/SIP/), encrypt = true/false + withSalt, rui, phoneNo, serverAddr; encrypted <body> payloads keyed by the registration random/reg-key (PBKDF2/AES-128-CBC, see registration.md).

  • Method/action words replace/augment numeric ids in the v2 envelope: methods Query/Control/Notify/Response; actions ConfirmInfo, OutdoorInfo, CameraInfo, QRInfo, Token, UnlockByPassword, PushStreamType, CallLadder, LeaveMessage, PickupWhenLM (literals @0x00120138).

  • Result/error: Result/Success, errorCode, errorMsg (xml_parse_result_v2 @0x001237d8); ringId (door-bell), responseStatusStrg on the ISAPI side.

  • Password mgmt: oldPassword/newPassword (0x0031c1a4); msgType on internal/SDK queues (cli_msg_task @0x001363b0, 0x00101f6c).

  • sipNum is absent from the V2 request builder’s emitted set (serial/ MAC/name/floor only; sipNum still parsed/used elsewhere — inferred demotion, not removal).

5. Heartbeat / MESSAGE shape

Same carrier: MESSAGE sip:sipCmd@<registrar>:5065, Content-Type: text/xml, videoIntercomMsg method=1 action=1 every ~119 s (0x77 threshold, identical constant on both sides), skipped while network down or devLongNum isn’t 11 chars; sipCmd remains a virtual AOR.

  • V1: task_sipClient_HeartBeat @0x000e28dc → sipcli_send_msg @0x000dc9b0 (vdm10_1.0/sip/client/heartbeat.c); body via xml_getSipInfoXml @0x000ea910; from-ip/to-ip + own devLongNum.

  • V2: cli_heartbeat_task @0x00133668 → cli_send_sip_cmd @0x0012c8bc (sip/client/{heartbeat,device_helpers}.c); same field set plus serial; on failure posts registration event 5 + UI status 9 — heartbeat loss now actively trips re-registration (inferred from sip_client_post_registration_event(5)).

8. Transport/encoding notes

  • text/xml bodies are still LF/CRLF-mixed templates on the client; the V2 registrar parses them with TinyXML — entity-escaping now matters (see registration.md checklist).

  • V2 adds an XML writer API (sip_xml_writer_*, sip/client/xml_writer.c) producing the same tag vocabulary — output shape is preserved while the generator changed.

  • Expires handling: V1 client sent fixed 900 (kinds 1/3/8) / door-reg cfg+0x350ce*60; V2 registrar echoes the request Expires in the response and the client derives per-role values (cli_send_regist role→expires; cli_reg_resp_proc reads expires from the response) — inferred role-based expiry.

  • IPv6 appears end-to-end in V2 SIP (sip_config_get_ipv6_mode @0x00230b2c picks AF_INET vs AF_INET6 sockaddr handling in sip_server_register_device; IP6 SDP templates; inet_pton in xml_parse_head_v2). V1 was IPv4-only.
